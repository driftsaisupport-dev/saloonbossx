Seller runbook · SaloonBossX 5.5.3

From zip file to first sale

Do phases 01 to 08 once, on a laptop, in order. About 2 hours. After that, each sale takes two minutes and each salon sets itself up with the in-app checklist. Tick the checks as you go; they are remembered in this browser.

App (APK)Billing, AI, data on the salon's phone
Licence sheetYour Google Sheet + Code.gs: keys, devices, renewals
Cloud bridgeBranchSync.gs in a new Gmail: backups, branches, bookings
Booking websiteGitHub Pages: short links customers open
00

What you need

10 min
  • A laptop (Windows or Mac) with Node.js 22 from nodejs.org, and a code editor such as VS Code.
  • Your personal Gmail (for the licence sheet) and one new Gmail only for the cloud bridge.
  • A free GitHub account (for the booking website) and a free Expo account at expo.dev (for building the APK).
  • An Android phone with Expo Go from the Play Store, and a second phone for testing.
  • The files from this chat: SaloonBossX_v5.5.3.zip, SaloonBossX_Licence_Keys.xlsx, SaloonBossX_PRIVATE_KEY_keep_secret.zip.
01

Unzip the project and put the keys in place

15 min
  1. Unzip SaloonBossX_v5.5.3.zip to a folder, e.g. Documents/SaloonBossX. Use this new folder, not an older copy.
  2. Unzip the private key zip and copy keys/private.key into the project's keys folder.
  3. Back up private.key in two places now (pen drive + password manager). If you lose it you can never make keys for apps already sold.
  4. Open a terminal in the project folder and run:
npm install npm run preflight

Preflight will stop on missing .env values. That's expected until phase 05. Check that it does not say "private.key does NOT match the public key".

02

Licence sheet and licence server

15 min
  1. In your personal Google Drive: New → File upload → SaloonBossX_Licence_Keys.xlsx.
  2. Open it → File → Save as Google Sheets. Rename the new sheet exactly SaloonBossX Licenses. Delete the uploaded .xlsx so only one file has that name.
  3. In the sheet: Extensions → Apps Script. Delete the sample code, paste all of google-apps-script/Code.gs, Save.
  4. Gear icon Project Settings → Script properties → Add: name RESPONSE_SECRET, value: a long random text. Make one with the command below and keep a copy for phase 05.
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
  1. Choose the function setup in the toolbar → Run → allow access (Advanced → Go to project → Allow).
  2. Deploy → New deployment → gear → Web app. Execute as: Me. Who has access: Anyone. Deploy. Copy the URL ending in /exec.
03

Cloud bridge (backup, branches, booking)

10 min
  1. Sign in to your new Gmail (e.g. saloonbossx.cloud@gmail.com). Open script.google.com → New project.
  2. Paste all of google-apps-script/BranchSync.gs → Save.
  3. Deploy → New deployment → Web app. Execute as: Me. Who has access: Anyone (not "Anyone with Google account"). Deploy → Authorise.
  4. Copy the /exec URL. Open it in an incognito window: you must see {"ok":true,…"version":5}.

"Sorry, unable to open the file at present" in the incognito test means access is not set to Anyone, or you copied the editor or /dev link instead of /exec.

Updating this script later: Deploy → Manage deployments → ✏️ → Version: New version. Never "New deployment"; that changes the URL and disconnects every salon.

04

Booking website with short links

15 min
  1. On GitHub: + → New repository, named exactly <your-username>.github.io, Public → Create.
  2. Put the cloud URL into .env first (phase 05, line EXPO_PUBLIC_CLOUD_URL), then run:
npm run booking-site
  1. In the repository: Add file → Upload files → drag the 4 files from booking-site/dist/ (index.html, 404.html, config.js, .nojekyll) → Commit.
  2. Settings → Pages → Deploy from a branch → main / root → Save. Wait two minutes.
  3. Open https://<username>.github.io/test: "Booking not available" means it works.
npm run check-booking

This checks, from your laptop, that the cloud script is public and on version 5, and that the website is online and points at it. Every line should show ✔.

05

Fill in the .env file

5 min

Copy .env.example to .env and fill in these lines. Leave EXPO_PUBLIC_LICENSE_PUBKEY empty; the public key is built into the app.

EXPO_PUBLIC_SUPPORT_WHATSAPP=91XXXXXXXXXX EXPO_PUBLIC_SELLER_UPI=yourname@okaxis EXPO_PUBLIC_SELLER_NAME=SaloonBossX EXPO_PUBLIC_LICENSE_URL=https://script.google.com/macros/s/…licence…/exec SBX_RESPONSE_SECRET=the-same-text-as-RESPONSE_SECRET EXPO_PUBLIC_CLOUD_URL=https://script.google.com/macros/s/…cloud…/exec EXPO_PUBLIC_BOOKING_SITE=https://<username>.github.io EXPO_PUBLIC_TRIAL_DAYS=0 EXPO_PUBLIC_REFUND_DAYS=7
npm run preflight npm run eas-env

npm run eas-env copies these values into eas.json. Cloud builds never receive .env, so without this the APK you sell would have no WhatsApp number or cloud links. Run it again whenever you change .env.

06

Test in Expo Go

15 min
npx expo start -c
  1. Scan the QR with Expo Go. -c clears the cache; without it Expo Go can keep running old code and old settings.
  2. Finish first setup, then paste a Monthly key from your sheet → Activate. It should say "Valid until …".
  3. At the bottom of the activation screen, App key check must show I1CXwh. That ID belongs to the public key your 1,600 keys were signed with.
  4. Check the sheet: that row now has a Device ID, Status ACTIVE, and a real end date in Expiry.
07

Build the APK you sell

25 min (mostly waiting)
npm install -g eas-cli eas login eas build -p android --profile production-apk
  1. The first time, EAS asks to create a keystore: answer Yes. Expo stores it; keep the same Expo account forever, or later updates won't install over the old app.
  2. When the build finishes, download the .apk from the link.
  3. Upload it to Google Drive (Anyone with the link → Viewer) or a GitHub Release, and use that link for customers.
  4. Every new version: raise versionCode in app.json, run npm run eas-env, then build again.

Renewals and daily support

SituationWhat you do
Monthly customer pays againSend the next Monthly key of the same plan. The app adds 31 days after their current end date. Or change that row's Expiry to the new date and ask them to tap "I have already paid — check again".
Customer changed phoneClear Device IDs, set Devices Used to 0 and Status to AVAILABLE in that row. They activate again, then restore with their recovery key.
Refund or misuseSet Status to REVOKED. The app locks at its next daily check.
More keysnpm run batch -- --plan standard --billing monthly --count 200, then File → Import → Append in the sheet.
Error report from a salonThey send it from the app on WhatsApp; it lists the screen and error. Fix, raise versionCode, rebuild, send the new APK link.
11

Fix: "That licence key is not valid"

Your key SBX-eyJwIjoic3RhbmRhcmQi… is genuine: it is a Salon Pro Monthly key, order SPM-20261002-0001, and it verifies with your public key I1CXwh…. When the app rejected it, the app was checking with a different public key. The usual causes, all fixed in 5.5.3:

  • An older project folder, or an old EXPO_PUBLIC_LICENSE_PUBKEY in .env, overrode the new key. 5.5.3 builds your public key into the code and trusts it no matter what .env says.
  • Expo Go was running cached code. Start it with npx expo start -c.
  • The key was typed, or WhatsApp added invisible characters or line breaks. 5.5.3 adds a Paste key button and cleans up pasted text.

To check quickly: the activation screen shows App key check: I1CXwh. If it shows anything else, you are running an old build or folder.
