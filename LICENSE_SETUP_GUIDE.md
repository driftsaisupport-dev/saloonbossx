# SaloonBossX — License Setup Guide
## Complete Step-by-Step Instructions

---

## PART 1: Generate License Keys (Offline — No Server Needed)

You can start selling immediately using offline keys.
No Google account or server required for this.

### Step 1: Open terminal in the project folder
```bash
cd /path/to/SaloonBossX
```

### Step 2: Generate keys
```bash
node generate-license-key.js
```

You will see a table like this:
```
STARTER    | LIFETIME     | SBX-STARTER-LIFETIME-XXXXXXXX
PRO        | LIFETIME     | SBX-PRO-LIFETIME-XXXXXXXX
BUSINESS   | LIFETIME     | SBX-BUSINESS-LIFETIME-XXXXXXXX
PRO        | 2026-12-31   | SBX-PRO-2026-12-31-XXXXXXXX
```

### Step 3: Generate a custom key for a customer
```bash
# Lifetime key for PRO plan
node generate-license-key.js BUSINESS LIFETIME

# Annual key expiring Dec 31 2026
node generate-license-key.js PRO 2026-12-31

# Starter plan expiring in 6 months
node generate-license-key.js STARTER 2026-02-28
```

### Step 4: Send the key to your customer
WhatsApp or email the key — e.g. `SBX-PRO-LIFETIME-XXXXXXXX`

The customer enters it in the Activation screen and taps "Activate".

## PART 2: Set Up Google Sheet for Online License Management
### (Optional but recommended — lets you track purchases, revoke keys, see device IDs)

### Step 1: Create a Google Sheet
1. Go to [sheets.google.com](https://sheets.google.com)
2. Create a new spreadsheet
3. Name it: **SaloonBossX Licenses**
4. Add these headers in Row 1 (or just run the script once — it creates the
   sheet and headers automatically):
   ```
   A: license_key | B: plan | C: expiry | D: device_ids | E: customer_name | F: customer_email | G: status | H: created_at | I: activated_at | J: activation_count
   ```
   - `plan` must be `starter`, `pro`, or `business` (device limits: 1 / 3 / 999).
   - `expiry` is `LIFETIME` or a date like `2026-12-31`.
   - `device_ids` — **leave blank**. The app fills this the first time the key is
     activated and appends more devices (separated by `|`) up to the plan limit.
     To move a customer to a new phone, clear this cell (or run `resetDevices`).
   - `status` — `active`; set to `revoked` to kill the key on the next check.
5. Copy the **Sheet ID** from the URL:
   `https://docs.google.com/spreadsheets/d/THIS_IS_YOUR_SHEET_ID/edit`

### Step 2: Create the Apps Script
1. In your Google Sheet, click **Extensions → Apps Script**
2. Delete all existing code
3. Open the file `google-apps-script/Code.gs` from this project
4. Replace `YOUR_GOOGLE_SHEET_ID` with your actual Sheet ID
5. Click **Save** (Ctrl+S)

### Step 3: Deploy as Web App
1. Click **Deploy → New deployment**
2. Click the gear icon ⚙️ next to "Type" → Select **Web app**
3. Set:
   - **Execute as:** Me
   - **Who has access:** Anyone
4. Click **Deploy**
5. Copy the **Web app URL** — it looks like:
   `https://script.google.com/macros/s/ABCDEF123.../exec`

### Step 4: Add the URL to your app
Open `.env` file in the project root (create it if it doesn't exist):
```env
EXPO_PUBLIC_LICENSE_URL=https://script.google.com/macros/s/AKfycbwOQCNBWBhIavUcvLFkn05nzBkbgY8VGQ4bRAyStuErctDo92c12xB-iJqxfDf3SKUrzQ/exec

```

Then rebuild the app:
```bash
eas build --platform android --profile production
```

### Step 5: Add a license to the Google Sheet (optional)
With the current `Code.gs`, a valid key generated by `generate-license-key.js`
is registered automatically in the `Licenses` sheet on its first activation.
You can still add a row manually when you want to pre-create customer details:
| license_key | plan | expiry | device_ids | customer_name | customer_email | status |
|---|---|---|---|---|---|---|
| SBX-PRO-LIFETIME-XXXXXXXX | pro | LIFETIME | (leave blank) | John's Salon | john@x.com | active |

**A key must be valid and have `status = active`.** On the first activation the app
creates or updates the row and writes the device ID, email and timestamp into it
and locks the key to that device. Further devices are allowed only up to the
plan limit (starter 1, pro 3, business unlimited); any device beyond the limit
is rejected with "already active on another device".

### Step 6: Revoke a license
Change the `status` column from `active` to `revoked`.
The key is rejected on the next online check (and on the customer's next app launch).

### Step 7: Move a customer to a new phone
Clear the `device_ids` cell for that row (or run the `resetDevices` function in
the Apps Script editor). The customer can then activate on the new device. The
customer can also self-serve from **Settings → License & Plan → Deactivate this
device** before switching phones.

### Step 8: After changing Code.gs — REDEPLOY
The app talks to a fixed `/exec` URL. After editing `Code.gs`:
**Deploy → Manage deployments → (pencil/Edit) → Version: New version → Deploy.**
This keeps the same URL, so you do **not** need to touch `.env` or rebuild the app.
(Only "New deployment" creates a new URL.)

## PART 3: Build & Publish the App

### Prerequisites
```bash
npm install -g eas-cli
eas login
```

### Configure eas.json (create if missing)
```json
{
  "cli": { "version": ">= 3.0.0" },
  "build": {
    "production": {
      "android": {
        "buildType": "apk",
        "gradleCommand": ":app:assembleRelease"
      }
    }
  }
}
```

### Build Android APK
```bash
eas build --platform android --profile production
```

### Build for Google Play Store (AAB format)
```json
"production": { "android": { "buildType": "app-bundle" } }
```
```bash
eas build --platform android --profile production
```

### Test on device before building
```bash
npx expo start
# Scan QR code with Expo Go app
```

## PART 5: Quick Support Checklist

When a customer says "license not working":
1. Ask them to share their exact key (copy-paste, no photos)
2. Check: no extra spaces before/after the key
3. Check: format is `SBX-PLAN-EXPIRY-XXXXXXXX`
4. If using online validation, check your Google Sheet — is the key listed with `status = active`?
5. Generate a fresh key using `node generate-license-key.js` and send it again

---

## PART 6: Important Security Notes

1. **Keep `generate-license-key.js` private** — do NOT share it with customers or post it online
2. **Keep the `OFFLINE_SECRET` in `LicenseService.ts` private** — if you change it after shipping, old keys stop working
3. The Google Sheet is protected by your Google account — use 2FA on that account
4. If someone generates fake keys (unlikely but possible), you can change `OFFLINE_SECRET`, rebuild the app, and issue new keys to all customers
